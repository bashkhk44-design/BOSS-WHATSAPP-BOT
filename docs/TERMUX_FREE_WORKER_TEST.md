# تشغيل Worker تجريبي مجاني من Termux

هذا الإجراء يشغّل عامل الطابور يدوياً على هاتف Android عبر Termux. لا ينشئ خدمة استضافة ولا يغيّر Render أو Webhooks أو بوتات الإنتاج.

## شروط السلامة

- استخدم اتصال Neon الخاص بفرع الاختبار فقط.
- لا تستخدم DATABASE_URL الخاص بالإنتاج.
- يجب أن يحتوي فرع الاختبار على migrations الخاصة بالطابور مطبقة مسبقاً.
- مفتاح BOTS_ENCRYPTION_KEY يجب أن يطابق المفتاح الذي شُفّرت به رموز البوتات الموجودة في قاعدة الاختبار. لا ترسله في المحادثة ولا تضعه في Git.
- لا تشغّل هذا العامل على قاعدة الإنتاج؛ عامل الاختبار قد يلتقط المهام الموجودة في الطابور.
- لا تنفّذ npm run db:migrate هنا. هذا الدليل لا يطبق أي ترحيلات.

## التجهيز على Termux

من مجلد نسخة المشروع:

```bash
pkg update -y && pkg install -y git nodejs-lts
node -v
```

يلزم Node.js 22 أو أحدث. بعد جلب الفرع الذي يحتوي هذا الملف، نفّذ:

```bash
cp .env.worker.example .env.worker.local
nano .env.worker.local
```

املأ القيم محلياً:
- DATABASE_URL: رابط Neon لفرع الاختبار حصراً.
- BOTS_ENCRYPTION_KEY: المفتاح الحالي المطابق لتشفير بيانات قاعدة الاختبار.
- اترك BOSS_WORKER_MODE و BOSS_TEST_DATABASE كما هما.

ثم شغّل:

```bash
chmod +x scripts/termux-worker.sh
./scripts/termux-worker.sh
```

أوقف العامل باستخدام CTRL+C. لا تتركه يعمل بالخلفية أثناء تشغيل عامل آخر على نفس قاعدة الاختبار.

## ما الذي يفعله السكربت؟

1. يرفض التشغيل ما لم تؤكد صراحةً أن الوضع اختبار وقاعدة البيانات تجريبية.
2. يتحقق من Node.js 22+ ومن شكل مفتاح التشفير.
3. يثبت الحزم عند الحاجة.
4. يختبر اتصال PostgreSQL بقراءة بسيطة فقط.
5. يشغّل `npm run start:worker`.

هذا لا يرسل رسائل اختبار إلى Telegram من تلقاء نفسه. كما أن تشغيل Worker وحده لا يعني أن Webhook يستقبل تحديثات؛ نختبر استقبال التحديثات لاحقاً بخدمة منفصلة وببوت تجريبي فقط.
